## 3. Docker 构建与部署验收

### 3.1 构建

执行 `deploy/deploy.sh`，多阶段构建成功：

- 构建阶段：`golang:1.27-alpine`，`CGO_ENABLED=0` 静态编译；
- 运行阶段：`alpine:3.21`，非 root 用户 `ulp`（uid 10001）；
- 产物：`/usr/local/bin/ulpd`、`/usr/local/bin/ulp-verify`；
- 镜像：`unified-license-platform:1.0.0`。

构建过程中处理的环境问题：

1. Dockerfile 顶部 `# syntax=docker/dockerfile:1` 需要额外拉取前端镜像，网络受限时失败，已移除并使用内置构建器；
2. 构建容器访问 `proxy.golang.org` 超时，Dockerfile 增加 `ARG GOPROXY=https://goproxy.cn,direct`；
3. 挂载宿主目录后容器用户 10001 无法写入 `data/`，`deploy.sh` 增加 `chown -R 10001:10001 data`；
4. `deploy.sh` 首次部署输出初始密码的变量引用错误已修正。

## 5. 已知限制与后续工作

1. **吊销的离线可见性**：授权文件为离线自包含格式，已下载的授权无法感知平台侧吊销；界面与文档已明确提示，需通过续期/换发或停机处理。
2. **时间回拨检测**：依赖本地检查点文件（`clock.dat`），仅能检测同一部署实例上的回拨，无法防御全新环境首次运行即改时钟的场景。
3. **四个业务项目接入**：AgentSystem、webb-api、virtual-employee、teable 的改造（P5~P10）尚未实施，接入方法见 `docs/接入统一授权平台-适配开发规范.md`。
4. **生产加固建议**：启用 HTTPS 反向代理、限制 7630 来源、配置数据与 `.env` 的定期异地备份。
